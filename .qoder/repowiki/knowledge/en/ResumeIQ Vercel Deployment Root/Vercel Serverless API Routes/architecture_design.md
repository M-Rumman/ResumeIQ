Each file is a standalone Vercel serverless function exporting a default `handler(req: VercelRequest, res: VercelResponse)` entry point. Routes are organized by feature domain — resume analysis (`analyze-resume.ts`), interview prep (`interview-prep.ts`), job matching (`job-match.ts`), payments (`create-checkout.ts`, `manage-subscription.ts`), report export (`export-resume-report.ts`), testimonials (`submit-testimonial.ts`), and diagnostics (`ai-health.ts`). All routes delegate cross-cutting concerns to the sibling `_lib/` directory: authentication via `getUserFromRequest`, input validation and body-size enforcement via `requestLimits.js`, rate limiting via `rateLimit.js` / `billingRateLimit.js` / `ipThrottle.js`, billing/feature access via `billing.js` and `featureAccess.js`, AI calls through `openrouter.js` / `geminiJobMatch.js`, persistence through `aiPersistence.js` and `supabaseAdmin.js`, and error handling via `safeError.js`. The `job-match.ts` route additionally handles sub-actions via `req.query.action` (e.g. `saved`) to perform CRUD on `saved_jobs`. The `ai-health.ts` route is a privileged diagnostic endpoint gated by an `x-ai-health-secret` header that optionally probes OpenRouter with a real API call. Dependency direction is strictly one-way: routes depend on `_lib/*` utilities but never import from other route files.
