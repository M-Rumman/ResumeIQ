The workspace is deployed to Vercel with `vercel.json` acting as the single entrypoint: it sets the build command to run inside the `project/` subdirectory, rewrites `/api/*` to the Node serverless handlers under `project/api/`, and falls all other routes through to `project/dist/index.html` for client-side routing. The three top-level test scripts (`test_bulletScoring.ts`, `test_frontend_filtering.ts`, `test_validateRewrites.ts`) exercise shared business logic in `project/api/_lib/analysis-engine/` (bullet scoring, resume extraction, AI validation) by importing those modules directly from the repo root, while `test_frontend_filtering.ts` also bridges backend results into the frontend via `src/lib/api/mapAiResults.js`. Security headers and a strict CSP are applied globally at the Vercel edge layer so both API routes and the SPA share the same security posture.
